# 🧪 Automated Testing Engine (Pascal TDD & BDD)

**BlaiseVue** features a native, zero-configuration automated testing engine written in **pure Object Pascal**, fully integrated with **Vitest** and **JSDOM**.

It empowers developers to test both **pure business logic** (domain rules, calculation engines, services, and models in Pascal) and **visual components and full route views** (`.bv`), delivering modern web testing speed with traditional Pascal type safety.

---

## 🎯 Why Automated Testing in BlaiseVue?

Coming from Delphi or Lazarus desktop development, you may be familiar with the tedious cycle of clicking buttons in a running application only to uncover a runtime nil pointer or validation error.

In BlaiseVue, you do not need to manually boot a browser and fill in forms after every code change:
1. You write test suites in **familiar Pascal syntax** (`Describe`, `It`, `Expect`).
2. BlaiseVue mounts components and views in an in-memory virtual DOM (**JSDOM**).
3. Tests simulate mouse clicks, keyboard input, and assertions on reactive DOM updates.
4. The entire test suite executes in seconds directly in the terminal!

---

## 📂 4-Tier Testing Architecture (`tests/`)

When you scaffold any new project with `bv create <ProjectName>`, BlaiseVue natively creates an enterprise-ready **4-tier testing hierarchy**:

```text
my-app/
├── src/
│   ├── components/          <- Visual components (.bv)
│   ├── views/               <- Route views & pages (.bv)
│   └── services/            <- Pure Pascal business logic & calculation services (.pas)
└── tests/
    ├── components/          <- Auto-generated by "bv new c <Name>"
    │   ├── ProductCard.test.pas
    │   └── HeaderBar.test.pas
    │
    ├── views/               <- Auto-generated by "bv new v <Name>"
    │   ├── DatasetView.test.pas
    │   └── CustomerView.test.pas
    │
    ├── unit/                <- Created via "bv new t <Name>" (business rules, calculations, services)
    │   ├── CalculadoraFrete.test.pas
    │   └── Formatters.test.pas
    │
    └── framework/           <- BlaiseVue core verification tests (Reactivity, Routing, DataSet, etc.)
        ├── dataset_offline.test.pas
        └── reactivity.test.pas
```

This clear architectural segregation guarantees that:
* **Component Tests** remain isolated, validating default/custom props, emitted events, and slots.
* **View Tests** simulate real end-user journeys (modal openings, CRUD operations, form submissions).
* **Unit Tests** verify mathematical formulas, tax rules, and service logic without DOM overhead.
* **Framework Tests** ensure the underlying reactive runtime, routing, and datasets remain 100% stable.

## ⚡ Automatic Test Generation (Zero Configuration)

Every component or view created through the CLI is immediately paired with its corresponding test file:

### 1. Creating a Component with an Automated Test
```bash
bv new component ProductCard
# Or quick alias:
bv new c ProductCard
```
The CLI automatically creates two files:
1. `src/components/ProductCard.bv` (Visual Single-File Component)
2. `tests/components/ProductCard.test.pas` (Pre-configured component test suite)

### 2. Creating a View with an Automated Test
```bash
bv new view OrderHistory
# Or quick alias:
bv new v OrderHistory
```
The CLI automatically creates:
1. `src/views/OrderHistory.bv` (Application page)
2. `tests/views/OrderHistory.test.pas` (View mounting and rendering test suite)

## 🚀 Prototyping without Tests (`--no-test`)

If you are rapidly prototyping and prefer to skip test generation, supply the `--no-test` (or `-nt`) flag:

```bash
bv new component SimpleBadge --no-test
bv new view Dashboard --no-test
```
The `.bv` file is scaffolded without creating any test file.

### 🧠 Smart Detection (`bv new test`)
When you are ready to write tests for an existing component or view, simply run:

```bash
bv new test SimpleBadge
# Or:
bv new t SimpleBadge
```

The BlaiseVue CLI inspects your workspace automatically:
1. **Found `SimpleBadge.bv` in `src/components/`?** Creates `tests/components/SimpleBadge.test.pas` configured with `<simple-badge>` and `Mount`.
2. **Found in `src/views/`?** Creates `tests/views/SimpleBadge.test.pas` with `<simple-badge-page>` and `Mount`.
3. **No matching `.bv` found?** Creates `tests/unit/SimpleBadge.test.pas` for pure Pascal domain logic.

You can also target a specific subfolder directly:
```bash
bv new t unit/CalculadoraFrete
bv new t framework/CustomReactivity
```

## 📝 Example 1: Testing a Component with Default Props & `$emit`

BlaiseVue supports default prop values (`props: title: string = 'Default Title'`). The test suite validates both default props and custom prop overrides, as well as emitted component events:

```pascal
program formheader_test;

{$mode objfpc}

uses JS, Web, BVTestUtils, uFormHeader;

var
  Wrapper: TWrapper;
  CustomProps: TJSObject;

begin
  Register_uFormHeader;

  Describe('Component: FormHeader', procedure
    begin
       It('should mount component with default prop values', procedure
         begin
            Wrapper := Mount('form-header');
            Expect(Wrapper.Element <> nil).ToBe(True);
            Expect(Wrapper.Find('.form-header-title').textContent).ToContain('Formulário do Sistema');
         end);

       It('should accept custom prop overrides', procedure
         begin
            CustomProps := TJSObject.new;
            CustomProps['title'] := 'Customer Registration';
            Wrapper := Mount('form-header', CustomProps);
            Expect(Wrapper.Find('.form-header-title').textContent).ToContain('Customer Registration');
         end);

       It('should emit header-clicked event on title click', procedure
         begin
            Wrapper := Mount('form-header');
            TJSHTMLElement(Wrapper.Find('.form-header-title')).click;
            Expect(Wrapper.Emitted('header-clicked')).ToBe(True);
         end);
    end);
end.
```

## 📝 Example 2: Testing Full Route Views (e.g. `DatasetView`)

You can test complex multi-step user workflows on full page views:

```pascal
program datasetview_view_test;

{$mode objfpc}

uses JS, Web, BVTestUtils, uDatasetView;

var
  Wrapper: TWrapper;

begin
  Register_uDatasetView;

  Describe('View: DatasetView', procedure
    begin
       It('should mount view and render initial table', procedure
         begin
            Wrapper := Mount('dataset-view-page');
            Expect(Wrapper.Find('.dataset-view-page')).toBeDefined;
         end);

       It('should open creation modal upon clicking New Product button', procedure
         begin
            Wrapper := Mount('dataset-view-page');

            { 1. Assert modal backdrop is closed initially }
            Expect(Wrapper.Find('.crud-modal-backdrop') = nil).ToBe(True);

            { 2. Simulate user click on New Product button }
            TJSHTMLElement(Wrapper.Find('.crud-header-btns button:first-child')).click;

            { 3. Assert modal backdrop is rendered in DOM }
            Expect(Wrapper.Find('.crud-modal-backdrop')).toBeDefined;
         end);
    end);
end.
```

## 📝 Example 3: Pure Pascal Business Logic Unit Tests

Service and domain unit tests reside in `tests/unit/` and import units from `src/services/` (configured in `app.cfg` via `-Fusrc/services`):

```pascal
program calculadorafrete_unit_test;

{$mode objfpc}

uses JS, Web, BVTestUtils, uCalculadoraFrete;

begin
  Describe('Unit: CalculadoraFrete (Domain Calculations)', procedure
    begin
       It('should apply free shipping for orders exceeding $250.00', procedure
         begin
            Expect(CalcularFrete('01001-000', 5.0, 300.0)).ToBe(0.0);
            Expect(CalcularFrete('40000-000', 10.0, 250.0)).ToBe(0.0);
         end);

       It('should calculate base fee for Southeast region under 1kg', procedure
         begin
            Expect(CalcularFrete('01001-000', 0.5, 100.0)).toBe(15.0);
         end);

       It('should identify correct delivery region and estimated timeframe', procedure
         begin
            Expect(RegiaoPorCEP('01310-100')).toBe('Sudeste - SP');
            Expect(PrazoEntregaDias('01310-100')).toBe(2);
         end);
    end);
end.
```

## 💡 Idiomatic Pascal with Optional JavaScript Power (`asm`)

In BlaiseVue, the standard approach is writing clean, type-safe **Object Pascal**.

However, the Pas2JS compiler fully supports inline `asm ... end;` blocks. This means when you need to mock external browser APIs, inject complex JSON payloads, or bridge third-party JavaScript libraries in your test suites, you have full JavaScript access without leaving your Pascal file:

```pascal
{ Example: Injecting complex mock structures via inline asm }
MockData := TJSObject.new;
asm
  $mod.MockData.items = [
    { id: 1, name: 'Optical Mouse', price: 89.90 },
    { id: 2, name: 'Mechanical Keyboard', price: 350.00 }
  ];
end;
```

Pascal remains the core of your developer experience, while `asm` acts as a seamless escape hatch when needed.

## 🛠️ Methods & Assertions Reference (`BVTestUtils`)

### 🧩 Mounting & DOM Querying
| Method | Description |
|---|---|
| `Mount(TagName, Props)` | Mounts component or view into virtual DOM and returns `TWrapper`. |
| `Wrapper.Find(Selector)` | Queries the first matching DOM child element by CSS selector. |
| `Wrapper.FindAll(Selector)` | Returns a `TJSArray` containing all matching child DOM elements. |
| `Wrapper.Element` | Returns the root `TJSHTMLElement` of the mounted wrapper. |
| `Wrapper.Text` | Returns rendered visible text content (`textContent`). |
| `Wrapper.HTML` | Returns the inner HTML markup (`innerHTML`). |

### 🖱️ Actions, Events & Triggers
| Method | Description |
|---|---|
| `TJSHTMLElement(El).click` | Simulates a native DOM mouse click event. |
| `Wrapper.SetValue(Value)` | Sets input value and dispatches reactive `input` and `change` events. |
| `Wrapper.Emitted(EventName)` | Returns `True` if the component fired `$emit(EventName)`. |
| `WaitTick` | Awaits the next asynchronous reactive DOM reconciliation flush. |

### ⚖️ Assertion Engine (`Expect`)
| Assertion | Description |
|---|---|
| `Expect(A).ToBe(B)` | Strict equality comparison (`===`). |
| `Expect(Text).ToContain(Substring)` | Asserts substring presence in text or array elements. |
| `Expect(Text).NotToContain(Substring)`| Negative assertion (asserts absence of CSS class or substring). |
| `Expect(El).toBeDefined` | Asserts element is defined and non-nil in DOM. |
| `Expect(Condition).ToBe(True)` | Asserts boolean expression evaluates to true. |
| `Expect(List).ToHaveLength(N)` | Asserts array or collection has exact length `N`. |

## 🚀 Running Test Suites

To recursively compile and execute all tests across all four tiers, run at project root:

```bash
bv test
```

BlaiseVue executes an automated 3-stage pipeline:
1. **Transpile**: Transpiles all `.bv` files into Pascal units under `generated/`.
2. **Compile**: Compiles `.test.pas` files to JavaScript in `generated/tests/` preserving folder hierarchy.
3. **Execute**: Runs tests via **Vitest** in JSDOM and outputs formatted terminal reports.

For continuous test-driven development:
```bash
bv test --watch
```

## 🗑️ Removing Components, Views & Tests

The `remove` command cleans up source code, generated Pascal units, and associated test files together:

```bash
# Removes component and tests/components/ProductCard.test.pas
bv remove component ProductCard

# Removes view and tests/views/OrderHistory.test.pas
bv remove view OrderHistory

# Removes a specific test file across any subfolder
bv remove test SimpleBadge
```
